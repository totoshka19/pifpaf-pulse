## 1. Стек

| Слой | Выбор | Почему |
|---|---|---|
| Фреймворк | **Next.js 15 (App Router) + TypeScript** | Фронт и бэк в одном деплое. TS компилируется в JS — требование «джаваскрипт» выполнено, а типы читаются как плюс. |
| БД | **PostgreSQL** (Neon или Supabase, free tier) | Требование «скл». Neon даёт бесплатный serverless-Postgres с branching. |
| Доступ к БД | **Drizzle ORM** + сырой SQL для аналитики | Drizzle — SQL-first, миграции нормальные. Тяжёлые запросы пиши руками через `sql\`\`` — они это и хотят увидеть. |
| Auth | Свой на JWT в httpOnly cookie + `bcryptjs` | За 24 часа это 40 минут работы против часов возни с настройкой Auth.js. |
| UI | Tailwind + shadcn/ui + Framer Motion | Быстро и не выглядит как бутстрап 2015 года. |
| Графики | **Recharts** | Ставится за минуту, выглядит прилично из коробки. |
| Данные | **Apify API** | Прямо указано в ТЗ. |
| Хранилище обложек | Supabase Storage / Vercel Blob / S3 Selectel | Обязательно. См. раздел 4 — это главная ловушка. |
| Деплой | **Vercel** + запасной вариант | См. раздел 9. |

**Не бери:** Prisma (медленные холодные старты на serverless + прячет SQL, который
как раз хотят увидеть), Redis (не нужен), микросервисы, Docker Compose из пяти
контейнеров. Всё это съест часы и не добавит баллов.

## 2. Архитектура

```
[Блогер] ──вставляет ссылку──> POST /api/reels
                                    │
                                    ├─ валидация URL, извлечение shortcode
                                    ├─ дедуп по (user_id, shortcode)
                                    ├─ INSERT reels (status='pending')
                                    └─ запуск Apify run (async) ──> сохраняем run_id
                                              │
                        ┌─────────────────────┴──────────────────┐
                        │                                        │
              Apify webhook на /api/apify/webhook      воркер-поллер (fallback)
                        │                                        │
                        └─────────────────┬──────────────────────┘
                                          │
                        забираем dataset items → нормализуем
                                          │
                        ├─ UPDATE reels (caption, posted_at, ...)
                        ├─ INSERT reel_snapshots (views, likes, comments)
                        └─ скачиваем обложку → свой сторадж → thumbnail_key

[Cron раз в N часов] ──> /api/cron/sync ──> берёт рилсы с last_synced_at старше N
                                            → батч-запуск Apify (один run на много URL)
                                            → новые snapshots
```

Ключевая идея: **`reels` — сущность, `reel_snapshots` — временной ряд**.
Без снапшотов не будет ни графиков, ни слова «обновляется».

## 3. Схема БД

```sql
CREATE TABLE users (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  email           TEXT UNIQUE NOT NULL,
  password_hash   TEXT NOT NULL,
  display_name    TEXT NOT NULL,
  instagram_handle TEXT,
  avatar_url      TEXT,
  role            TEXT NOT NULL DEFAULT 'blogger',  -- 'blogger' | 'admin'
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE reels (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id         UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  shortcode       TEXT NOT NULL,
  url             TEXT NOT NULL,
  caption         TEXT,
  owner_username  TEXT,
  thumbnail_key   TEXT,            -- ключ в нашем сторадже
  thumbnail_src   TEXT,            -- оригинальный CDN-URL (для отладки)
  posted_at       TIMESTAMPTZ,
  duration_sec    NUMERIC(6,2),
  sync_status     TEXT NOT NULL DEFAULT 'pending', -- pending|ok|failed|private
  sync_error      TEXT,
  last_synced_at  TIMESTAMPTZ,
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (user_id, shortcode)
);

CREATE TABLE reel_snapshots (
  id          BIGSERIAL PRIMARY KEY,
  reel_id     UUID NOT NULL REFERENCES reels(id) ON DELETE CASCADE,
  views       BIGINT,
  plays       BIGINT,
  likes       BIGINT,
  comments    BIGINT,
  captured_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE sync_runs (
  id            BIGSERIAL PRIMARY KEY,
  reel_id       UUID REFERENCES reels(id) ON DELETE CASCADE,
  apify_run_id  TEXT,
  status        TEXT NOT NULL,     -- running|succeeded|failed
  error         TEXT,
  started_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  finished_at   TIMESTAMPTZ
);

CREATE INDEX idx_reels_user        ON reels(user_id);
CREATE INDEX idx_reels_sync        ON reels(last_synced_at NULLS FIRST);
CREATE INDEX idx_snapshots_reel_ts ON reel_snapshots(reel_id, captured_at DESC);
```

### SQL, который стоит написать руками (это витрина)

**Последний снапшот по каждому рилсу — `DISTINCT ON`:**

```sql
SELECT DISTINCT ON (r.id)
       r.id, r.shortcode, r.caption, r.thumbnail_key, r.posted_at,
       s.views, s.likes, s.comments, s.captured_at
FROM reels r
LEFT JOIN reel_snapshots s ON s.reel_id = r.id
WHERE r.user_id = $1
ORDER BY r.id, s.captured_at DESC;
```

**Прирост просмотров за 7 дней — оконная функция:**

```sql
WITH ranked AS (
  SELECT s.reel_id, s.views, s.captured_at,
         ROW_NUMBER() OVER (PARTITION BY s.reel_id ORDER BY s.captured_at DESC) AS rn_new,
         ROW_NUMBER() OVER (PARTITION BY s.reel_id ORDER BY s.captured_at ASC)  AS rn_old
  FROM reel_snapshots s
  JOIN reels r ON r.id = s.reel_id
  WHERE r.user_id = $1 AND s.captured_at > now() - INTERVAL '7 days'
)
SELECT reel_id,
       MAX(views) FILTER (WHERE rn_new = 1) - MAX(views) FILTER (WHERE rn_old = 1) AS growth_7d
FROM ranked
GROUP BY reel_id
ORDER BY growth_7d DESC NULLS LAST;
```

**Динамика суммарных просмотров по дням (для графика):**

```sql
SELECT date_trunc('day', s.captured_at) AS day,
       SUM(s.views) AS total_views
FROM reel_snapshots s
JOIN reels r ON r.id = s.reel_id
WHERE r.user_id = $1
GROUP BY 1
ORDER BY 1;
```

**Лидерборд блогеров (админ-режим):**

```sql
WITH latest AS (
  SELECT DISTINCT ON (s.reel_id) s.reel_id, s.views, s.likes, s.comments
  FROM reel_snapshots s ORDER BY s.reel_id, s.captured_at DESC
)
SELECT u.display_name,
       COUNT(r.id)                                        AS reels_count,
       COALESCE(SUM(l.views), 0)                           AS total_views,
       ROUND(AVG(l.views))                                 AS avg_views,
       ROUND(100.0 * SUM(l.likes + l.comments)
             / NULLIF(SUM(l.views), 0), 2)                 AS er_percent
FROM users u
LEFT JOIN reels r ON r.user_id = u.id
LEFT JOIN latest l ON l.reel_id = r.id
GROUP BY u.id
ORDER BY total_views DESC;
```

Вынеси эти запросы в `src/db/queries/` отдельными файлами с комментариями. Если
проверяющий откроет репозиторий, он должен сразу увидеть, что SQL написан осознанно.

## 4. Apify: как не сжечь бесплатный тариф и не получить битые обложки

### Выбор актора

Начни с официального **`apify/instagram-scraper`** — он принимает прямые URL постов
и рилсов. Альтернатива — `apify/instagram-reel-scraper`.

**Первым делом (до всякого кода):** зарегистрируйся на Apify, открой актор в консоли,
скорми ему 2–3 реальные ссылки на рилсы и **посмотри глазами на JSON**. Формат полей
у акторов разный и меняется; гадать по документации — потеря часа.

Ожидаемые поля (проверь по факту): `shortCode`, `caption`, `displayUrl`,
`videoPlayCount` / `videoViewCount`, `likesCount`, `commentsCount`, `timestamp`,
`videoDuration`, `ownerUsername`.

> ⚠️ `videoViewCount` и `videoPlayCount` — разные метрики, и одна из них часто `null`.
> Логика: `views = videoPlayCount ?? videoViewCount ?? null`. Это ровно та «деталь»,
> на которую смотрят.

### Два режима запуска

```js
// Синхронно — только для одиночного добавления, если укладывается в ~50 сек
POST https://api.apify.com/v2/acts/apify~instagram-scraper/run-sync-get-dataset-items?token=***

// Асинхронно — для фонового обновления и батчей (правильный вариант)
POST https://api.apify.com/v2/acts/apify~instagram-scraper/runs?token=***
GET  https://api.apify.com/v2/actor-runs/{runId}?token=***
GET  https://api.apify.com/v2/datasets/{datasetId}/items?token=***
```

Не вызывай `run-sync` из serverless-функции с дефолтным таймаутом — упрёшься в лимит.
Либо `export const maxDuration = 60` в route handler, либо (лучше) async + поллинг с
фронта каждые 3 секунды, пока `sync_status = 'pending'`.

### Экономия кредитов (free tier — $5/мес)

- **Хард-лимит:** не синкать рилс чаще, чем раз в час (`last_synced_at`).
- **Батчинг:** cron собирает все устаревшие URL и запускает **один** run на все.
- **Дедуп:** один и тот же shortcode у одного юзера — не добавляем второй раз.
- **Rate limit:** не больше N добавлений в минуту на пользователя.
- **Кеш фикстур:** сохрани 5–10 реальных JSON-ответов в `fixtures/`. Флаг
  `APIFY_MOCK=1` подменяет реальные вызовы. Разрабатывай на моках, живые вызовы —
  только для проверки. Заодно это твой план Б, если кредиты кончатся в час X.

### 🔴 Главная ловушка: обложки Instagram

CDN-ссылки Instagram (`*.cdninstagram.com`) — **подписанные и протухающие**, плюс
блокируют хотлинк с чужих доменов. Если положишь `displayUrl` прямо в `<img src>`:

- у тебя локально всё покажется (браузер закеширует),
- **у проверяющего через сутки будет сетка пустых серых квадратов.**

Это самый вероятный способ провалить тест «на детали».

**Решение (обязательное):** при первой синхронизации скачиваешь обложку на сервере и
кладёшь в свой сторадж (Supabase Storage / Vercel Blob / S3 Selectel), в БД пишешь
`thumbnail_key`. Отдаёшь через `next/image` со своего домена.

Плюс страховка: компонент `<ReelCover>` с `onError` → красивый плейсхолдер с
градиентом и первой буквой автора. Никогда не показывай сломанную иконку картинки.


**Проверка владения на каждом эндпоинте:** `WHERE user_id = $session.userId`.
Отдельно протестируй: залогинься под демо-1, попробуй открыть `/api/reels/:id` от
демо-2 → должно быть 404, не 200 и не 403 с утечкой факта существования.

## 6. Экраны

### `/` — лендинг
Короткий, в стиле pifpafai.com: заголовок, одно предложение, скриншот дашборда,
кнопка «Войти» и «Демо-доступ» (кнопка сама подставляет демо-логин — экономит
проверяющему 30 секунд и это заметят).

### `/app` — дашборд
- Строка KPI: всего рилсов · суммарные просмотры · средние просмотры · ER% · прирост за 7 дней (со стрелкой и цветом)
- Большой график динамики просмотров (Recharts, area chart, переключатель 7д/30д/всё)
- Топ-3 рилса карточками
- Блок «Когда лучше постить» — гистограмма по дням недели/времени публикации из твоих же данных. Дешёвая фича, а выглядит как продуктовая аналитика.

### `/app/reels` — лента
- Переключатель вида: **сетка** (Pinterest-стиль, masonry, обложки 9:16) ↔ **таблица** (плотная «красивая БД» с сортировкой)
- Поле «вставь ссылку» всегда сверху, с кнопкой «Вставить из буфера»
- Сортировка, поиск по подписи, фильтр по периоду
- Карточка: обложка, просмотры крупно, лайки/комменты мелко, дата относительная, бейдж роста, кнопки «Обновить» / «Открыть в Instagram»

### `/app/reels/:id` — карточка рилса
Крупная обложка, все метрики, **график роста просмотров этого рилса по снапшотам**,
подпись, лог синхронизаций. Это экран, который продаёт всю идею «обновляется».

### `/app/settings` — профиль
Имя, инстаграм-хендл, аватар, смена пароля.

### `/app/team` — только админ
Лидерборд блогеров, сравнение, суммарные цифры по всем.

- [ ] Подтверждение при удалении
- [ ] Favicon, `<title>` на каждой странице, OG-картинка (проверяющий кинет ссылку в ТГ — превью увидят все)

- [ ] Плавное появление карточек (`stagger` в Framer Motion)
- [ ] Hover-состояния везде, где кликабельно
- [ ] Мобильная вёрстка — **обязательно**, блогеры сидят с телефона, и проверять, скорее всего, будут тоже с телефона

## 9. Деплой (решить в первый час, не в последний)

**Основной вариант: Vercel + Neon.** Бесплатно, деплой из коробки, домен
`*.vercel.app` сразу.

**Риск:** доступность Vercel из России бывает нестабильной, а проверять будут из
России. Проверь **в начале работы**, а не в конце: задеплой пустой Next.js и открой
его с мобильного интернета без VPN.

**Запасные варианты (если Vercel тормозит):**
- **Timeweb Cloud Apps** — деплой Next.js из GitHub, российская площадка
- **Amvera / Selectel** — Selectel им точно знаком, они на нём хранят файлы
- **VPS (~200₽/мес) + Docker + Caddy** — 40 минут работы, полный контроль

**Домен.** Купи на reg.ru что-нибудь вроде `reels-pifpaf.ru` за 200–300 рублей.

## 10. Тайминг

24 часа — это не 24 часа работы. Заложи 6–7 часов на сон, иначе последние четыре
часа уйдут на отладку опечаток. Реальный бюджет — **16–17 часов**.

|---|---|---|---|
| **0. Разведка** | 0:00–1:00 | Apify-аккаунт, ручной прогон актора, сохранение фикстур. Создание Neon-БД. Репозиторий + **деплой пустого Next.js на прод**. Проверка доступности с телефона. | Пустая страница открывается по публичному URL |

| **3. Обложки** | 6:00–7:00 | Скачивание и загрузка в сторадж, `next/image`, плейсхолдер на ошибку. | Обложки открываются со своего домена |
| **4. Лента** | 7:00–10:00 | Список рилсов: сетка + таблица, карточка, сортировка, удаление. | Кабинет выглядит как продукт |

## 11. Демо-данные — не пропусти этот пункт

Самая частая ошибка на таких тестовых: проверяющий заходит, видит форму регистрации,
регистрируется, видит пустой экран, добавляет один рилс, ждёт 40 секунд — и закрывает.
Дашборд с одной точкой на графике не производит впечатления.

**Что нужно:**
1. Два-три демо-аккаунта с 15–25 реальными рилсами.
2. **Сгенерированная история снапшотов за 30 дней** — правдоподобная кривая роста
   просмотров (быстрый рост в первые 48 часов, потом плато). Пиши сидом, не руками.
3. Кнопка «Войти как демо» на лендинге — один клик, без ввода пароля.
4. Один аккаунт с ролью `admin`, чтобы был виден лидерборд.

Честно укажи в README, что исторические снапшоты сгенерированы для демонстрации —
данные с Apify приходят реальные, но за один день истории не накопить. Это как раз
и есть «очеловеченность»: показать, что понимаешь ограничение, и обойти его красиво.

## 12. Работа с Claude Code (это тоже оценивают)

Вакансия про вайбкодинг — значит важен не только результат, но и то, как ты
организуешь работу с ИИ.

- Положи в корень `CLAUDE.md`: стек, конвенции, схема БД, «не используй Prisma»,
  «все SQL-запросы в `src/db/queries/`», «тексты интерфейса — на русском, на "ты"».
- Держи `PLAN.md` (этот файл) в репозитории и отмечай сделанное — Claude Code будет
  видеть прогресс.
- Работай вертикальными срезами: «схема + эндпоинт + экран» за раз, а не «весь бэкенд,
  потом весь фронт». Так у тебя всегда есть работающее приложение.
- Коммить осмысленно (`feat: apify sync pipeline`, а не `fix`). Гит смотреть не
  просили, но если откроют — история говорит о тебе больше кода.
- После каждого блока — коммит и деплой. Прод не должен ломаться.

## 14. Как сдавать

Отправлять в телеграм **@sergeyzolotykh**. Не просто ссылку — сообщение должно
работать само по себе:

```
Сергей, привет! Тестовое готово — назвал его PifPaf Pulse.

🔗 Сайт: https://pifpaf-pulse.ru
👤 Демо-доступ: на главной кнопка «Войти как демо»
   (или demo@pifpaf.ru / demo1234)
🎬 Видео-демо на 60 секунд: <ссылка на Loom / кружок>

Что внутри:
— Вставляешь ссылку на рилс → данные подтягиваются через Apify API
  (просмотры, лайки, комментарии, дата, обложка)
— Обложки кешируются в свой сторадж: ссылки Instagram протухают
  через сутки, иначе у вас была бы пустая сетка
— Метрики пишутся в историю снапшотов, поэтому есть графики роста
  по каждому рилсу и по кабинету
— Автообновление раз в час + кнопка «Обновить» вручную
— Личные кабинеты с изоляцией данных, есть админ-роль с лидербордом
  по всем блогерам
— Postgres, сложная аналитика на сыром SQL (оконные функции)

Что бы делал дальше: <2–3 пункта — командные проекты, интеграция
TikTok/YouTube Shorts, уведомления о вирусных рилсах в телеграм>

Код: <ссылка на GitHub>
```

**Перед отправкой обязательно:**
1. Открой сайт в режиме инкогнито с **телефона, с мобильного интернета**.
2. Пройди весь путь: лендинг → демо-вход → дашборд → добавление нового рилса → карточка.
3. Проверь, что превью ссылки в телеграме отрисовалось (OG-картинка).
4. Убедись, что сайт не «засыпает» — на бесплатных тарифах холодный старт может
   занять 10 секунд. Прогрей его за пять минут до отправки.

**Видео на 60 секунд стоит записать.** Если проверяющий откроет сайт с плохим
интернетом или в неудачный момент — видео спасёт впечатление. Плюс это ровно та
«очеловеченность», про которую написано в ТЗ.
