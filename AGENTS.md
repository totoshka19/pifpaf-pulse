### Незакрытые хвосты

- В `users` лежит `test@test.com` — ручная регистрация при проверке прода.
  Удалить или оставить до сидов среза 9. Отдельный, более старый хвост —
  не путать со свежими тестовыми аккаунтами ниже.
- **Перед показом работодателю перевыпустить** пароль базы Neon и токен Apify:
  оба засветились в переписке. В репозитории их нет — история проверена.
- Лимит «не чаще N в минуту на пользователя» из `PLAN.md` §7 **не реализован**.
  Почасовой лимит на рилс есть и считает попытки, а не успехи (проваленный
  прогон тоже стоил кредита, и кнопка «Повторить» обязана троттлиться);
  месячный `tryReserve` остаётся жёстким предохранителем независимо от обоих.
  Лимит на пользователя требует общего состояния между вызовами serverless-
  функции — таблица или колонка, это территория среза 7.
- Тестовые аккаунты копятся в общей с продом базе при каждой сквозной
  проверке: регистрировать на `@example.invalid` или `@example.test` и
  записывать адреса в отчёт, чтобы потом удалить одним запросом.

## Версии, которые уже сломали ожидания

Проверено по докам в `node_modules/next/dist/docs/`, не по памяти:

- **Next.js 16**, не 15. `middleware.ts` **устарел и переименован в `proxy.ts`**,
  экспорт функции — `proxy`, не `middleware`.
- **Proxy по умолчанию исполняется в Node.js-рантайме.** Опция `runtime` в proxy-файле
  недоступна и бросает ошибку при попытке её задать. Это НЕ Edge, как было до 15.2.
- `bcryptjs` 3.x везёт собственные типы — `@types/bcryptjs` не ставить, это пустая заглушка.
- `vitest.config.mts` — именно `.mts`. В package.json нет `"type": "module"`,
  и обычный `.ts` грузится как CommonJS, ломая `import.meta.url`.

## Конвенции

- **ORM — Drizzle. Prisma не использовать.** Она прячет SQL, который в этом задании
  как раз и хотят увидеть.
- **Аналитические запросы — сырым SQL в `src/db/queries/`**, отдельными файлами
  с комментариями. Это витрина навыка, а не деталь реализации.
- **`jose`, не `jsonwebtoken`.** Node-рантайм в proxy это позволяет, но `jose` не
  зависит от Node API и сохраняет живым запасной деплой на Cloudflare Workers (`PLAN.md` §13).
- **Всё время в интерфейсе и в группировках — `Europe/Moscow`.** `TIMESTAMPTZ`
  хранится в UTC; `date_trunc` без `AT TIME ZONE` сдвинет данные на три часа.
- **Тексты интерфейса — по-русски, на «ты»**, в тоне pifpafai.com. Ошибки объяснять
  человеческим языком, без кодов и `Error: fetch failed`.
- **Нет данных — это `—`, а не `0`.** Instagram отдаёт `-1` для скрытых лайков и
  `null` для части метрик; ноль — валидное значение и путать их нельзя.
- Изоляция данных: в каждом эндпоинте `WHERE user_id = $session.userId`.
  Чужая запись отдаётся как **404**, не 403.

## Грабли этого проекта — проверено на практике

Каждый пункт стоил времени. Не наступать заново.

| Грабли | Как обходить |
|---|---|
| В `package.json` нет `"type": "module"` | Любой файл с top-level `await` или `import.meta` — расширение **`.mts`**, не `.ts`. Так сделаны `vitest.config.mts`, `vitest.integration.mts`, `scripts/backfill-thumbnails.mts`. |
| `curl` в Windows-консоли **портит кириллицу** в теле запроса | Проверять API только клиентом на Node. Можно получить и ложную ошибку, и ложный успех. |
| `export * from './schema'` не виден из `.mts`-скриптов | ESM не видит реэкспорты сквозь границу с CJS. В скриптах импортировать таблицы прямо из `../src/db/schema`. |
| Кавычки в SQL делают имя регистрозависимым | После `AS "createdAt"` во внешнем запросе колонки `created_at` уже нет. |
| `require('sharp/package.json')` бросает ошибку | `exports` пакета не отдаёт `package.json`. Версия — через `require('sharp').versions`. |
| Netlify free: **10 секунд** на функцию, background-функций нет | Ни один запрос не ждёт Apify (прогон 14–19 с). Батчи в кроне резать по количеству. |
| `APIFY_MOCK=1` не должен трогать счётчик бюджета | Резерв вызывается как `!isMock() && await tryReserve(1)`. Иначе разработка за пару дней «выберет» месячный лимит и прод откажет в синхронизации. |
| Сырой `db.execute` отдаёт не только `BIGINT` строкой | Замерено на живой базе: `int` (int4) → число; **`bigint` → строка**; **`numeric` → строка**; **`timestamptz` → строка** в текстовом формате Postgres (`"2026-08-24 00:38:00+00"`); `bool` → boolean; `text`/`uuid` → строка; `NULL` → `null`. Типизированный `db.select().from(...)` не расходится — маппит сам. Даты опаснее чисел: непривёденная дата уронила всю ленту `TypeError: a.createdAt.getTime is not a function`, и вылезло это только при ДВУХ рилсах — `Array.prototype.sort` с одним элементом компаратор не вызывает, баг невидим. |
| `TaskStop` не убивает дочерний `next dev` | Освобождать порт через `taskkill /PID <pid> /F`. **Next 16.3.2 больше не печатает PID** дев-сервера в своём выводе (было раньше, проверено при исполнении задачи 6 среза 5) — искать через `netstat -ano`, отфильтровав строку с `:3000` (например, через `findstr`), последняя колонка и есть PID. |
| `eslint-plugin-react-hooks` 7.1.1 (`react-hooks/immutability`) не ловит мутацию массивов | Прямое присваивание в стейт (`row.syncStatus = x`) правило поймает. `.push()`/`.splice()` по массиву в стейте или пропах (`rows`, `initialRows`) — нет, слепая зона. Менять такой массив только через копию (`[...rows]`, `.filter`, `.map`). |
| Относительные даты в серверном компоненте ломают гидрацию | Сервер рисует «59 минут назад», клиент на своих часах через секунду — «1 час назад», React ловит расхождение разметки. Чинится пропом: серверный `Date.now()` уезжает в клиентский компонент, `useState` сеется им же для первого рендера, и только в `useEffect` после монтирования компонент переключается на часы браузера. |

## Приёмы, которые себя оправдали

- **Мутационная проверка.** После написания теста сломать защищаемый код и убедиться,
  что тест покраснел. Так выяснилось, что тест на `alg: none` ничего не проверял
  (jose и так его отвергает), а комментарий рядом утверждал обратное.
- **Смотреть на данные после прогона, а не только на счёт зелёных тестов.**
  Так найден баг с засорением счётчика Apify: все тесты проходили, ошибка жила
  на стыке двух корректных решений.
- **Замерять, а не оценивать.** Обложки оказались 43–70 КБ вместо «~30–40» из спеки,
  ссылки Instagram живут 4,5 суток, а не сутки. Обе цифры шли в письмо работодателю.
- **Режим прода читается из базы:** мок пишет в `sync_runs.apify_run_id` префикс
  `mock:`, живой Apify — настоящий id. База у прода и разработки одна.
- **Смотреть на компонент в работе, а не только в коде.** `<ReelCover>` собрался
  и прошёл ревью ещё в срезе 4, но открыть его в браузере руки дошли только
  в срезе 5 — и сразу нашёлся баг: `broken` был булевым флагом и не сбрасывался,
  поэтому обложка, отдавшая `404` до того, как файл реально появился, оставалась
  серым плейсхолдером до перезагрузки страницы. Починка — завязать сброс на
  ключ по версии синхронизации в URL, а не на факт однажды случившейся ошибки.
